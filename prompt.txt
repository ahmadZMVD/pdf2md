# 3. PHASE 2 SCOPE & ENGINEERING REQUIREMENTS

You are responsible for building the core conversion backend, IPC commands, and execution pipeline:

### TASK 1: Dynamic Tool Path Resolution Engine (Fixing PATH Dependency)
- Implement dynamic executable path resolution in Rust (`src-tauri/src/commands/`) and Python (`scripts/`):
  1. Primary Check: Inspect local application relative resource directory (`./resources/bin/` or `resources/bin/`).
  2. Fallback Check: Inspect system-wide `PATH` environment variable if local portable binaries are absent.
- Ensure the system resolves `python` and `pandoc` paths gracefully without crashing on system machines lacking installed tools.

### TASK 2: Asynchronous Subprocess Engine Wrappers
- **PDF Conversion Engine:** Integrate `PyMuPDF4LLM` via a dedicated Python subprocess handler (`scripts/pdf_engine.py`):
  - Extract text, headings, bullet lists, and tables cleanly into GitHub Flavored Markdown (GFM).
  - Extract PDF images to a dedicated folder named `[filename]_images/` alongside the output document.
  - Inject relative image Markdown links: `![image]([filename]_images/img_1.png)`.
- **DOCX & TXT Engine:** Integrate `Pandoc CLI` via async process invocation:
  - Convert DOCX and raw TXT files to GFM (`--from=docx --to=gfm` / `--from=markdown --to=gfm`).
  - Retain all mathematical notation, raw formulas, LaTeX blocks, and special characters without stripping.

### TASK 3: Sequential Queue Worker System (0% Crash Guarantee)
- Implement a thread-safe, sequential (one-by-one) Queue Worker in Rust:
  - Process queued files strictly sequentially to guarantee deterministic memory allocation and zero race conditions.
  - Instantly release RAM memory footprint back to baseline upon completing each file.
- **Incremental Filename Handling:** If an output file (e.g., `report.md`) already exists in the target destination, automatically append an incremental counter (`report_1.md`, `report_2.md`).
- **Error Handling & Unsupported Formats:**
  - Unsupported file extensions (e.g., `.zip`, `.exe`, `.jpg`) must be flagged as `Unsupported` and skipped without halting the queue.
  - Corrupted or encrypted PDFs must be caught gracefully, logged, and skipped as `Failed`, allowing the remaining queue items to finish.

### TASK 4: Frontend Mock IPC Contract Alignment
- Update `src/services/ipc.js` and Rust command handlers (`src-tauri/src/commands/conversion.rs`) to maintain strict contract parity:
  - Implement IPC commands: `start_conversion_batch`, `cancel_batch`, and `get_queue_status`.
  - Maintain full browser execution compatibility so that running Vite dev server locally (`npm run dev` / `npm run test:frontend`) mocks payload responses without throwing `window.**TAURI**` exceptions.

### TASK 5: Real-World Dataset Validation (`test_documents/`)
- Validate the processing pipeline against the real test documents suite in `test_documents/`:
  - `01_simple_text.pdf`
  - `02_two_column_scientific_paper.pdf`
  - `03_persian_rtl_document.pdf`
  - `05_equation_heavy_math.pdf`
  - `06_complex_tables.pdf`
  - `08_hybrid_pdf.pdf`
- Measure character count, processing latency, and execution stability per file.
